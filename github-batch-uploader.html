GitHub 批量上传工具 · 文件夹版

选整个文件夹 → 保留目录结构上传 → 仓库自动出现同名文件夹。令牌仅在你浏览器与 GitHub 之间传输。

使用前准备： ① 在 GitHub 创建好目标仓库； ② 生成个人访问令牌：GitHub → Settings → Developer settings → Personal access tokens，生成时勾选 repo 权限（Classic 令牌）； ③ 令牌只在你本地浏览器使用，本工具不会保存或上传它，用完建议在 GitHub 删除。
关于"文件夹"：Git 仓库里没有需要单独新建的空文件夹——文件夹是跟着文件路径自动生成的。 比如上传文件到 ACNZ的补丁/某补丁.pak，仓库里就会自动出现 ACNZ的补丁 文件夹， 点进去就是里面的文件，每个都能单独打开和下载。所以你只要选文件夹上传，结构就自动建好了。

点「📂 加载」列出仓库里已有的文件夹，点选即填入；也可手动输入。上传的文件会作为它的子内容放进去。

填仓库里的完整路径（含 patches/ 和分类），可用「📂 选文件」从仓库列表里挑。网站的匹配就靠它。
怎么区分：「📤 上传描述」= 把你上面填的写进仓库（填好描述点它即可，不用重新传补丁文件）；「↓ 拉取已有描述」= 把仓库里已有的读回来。第一次用时仓库没有描述文件，拉取显示 0 条是正常的。

上传说明

• 增量更新：本地按 Git 规则算文件指纹（已验证与 GitHub 返回的一致），与仓库里的对比，一样就跳过，只传新增/改动的文件。
• 新增文件上传后会成为独立文件；同名路径永远只有一个文件，覆盖更新，不会产生重复文件夹。
• 单个文件上限 100 MB（GitHub Contents API 限制）；超过 100 MB 的文件需改用 Git LFS，本工具不适用。
• 文件列表里的"仓库路径"就是上传后它在仓库里的位置，可先核对再上传。
• 只有真正上传/更新的文件才产生 commit，跳过的不会；遇到限流（403/429）会自动等待重试。
• 成功后日志给出每个文件的独立链接：点开即单文件页面 / 原始文件地址（raw.githubusercontent.com），方便单独调用。
• 描述同步：第 3 步填的描述会写进仓库的 patches/meta.json，网站打开时读取它显示你写的标题/简介/更新内容。留空字段不覆盖原有描述；描述文件的内容没变化不会产生多余提交。
